# VEMIO — AI Product Engineer Technical Case

Demand forecasting, price elasticity, and promotional uplift analysis on a
simulated CPG dataset, for the AI Product Engineer technical case at VEMIO.

## Deliverables

| File | Description |
|---|---|
| `VEMIO_Findings_Sibraim_Tejeda.pdf` | **Official methodology document (1-2 pages)** — assumptions, methodology for each challenge, trade-offs. This is deliverable #2 required by the case brief. |
| `docs/business_recommendations.md` | 3-5 business recommendations in non-technical language — deliverable #3. |
| `notebooks/vemio_case_analysis.ipynb` | Reproducible notebook with the full development of all 3 challenges — deliverable #1. |
| `docs/findings.md` | Extended technical write-up. Covers the same content as the PDF in more depth. **This is an optional appendix, not the required 1-2 page deliverable** — read the PDF for the official submission. |
| `src/data_cleaning.py` | Cleaning functions used by the notebook. |
| `data/20260806_prueba_tecnica_dataset.csv` | Original dataset provided for the case. |
| `outputs/` | Charts generated by the notebook (referenced in `docs/findings.md`). |

## How to run

```bash
pip install -r requirements.txt
jupyter notebook notebooks/vemio_case_analysis.ipynb
```

The notebook reads the dataset from `../data/20260806_prueba_tecnica_dataset.csv`
(path relative to `notebooks/`) and saves charts to `../outputs/`.

## Data dictionary

### Grain

Each row represents a transaction at the level of:
- Day
- Client
- Product
- Individual transaction (ticket)
- Promotion the product was sold under (if any)

### Column dictionary

| Column | Description |
|---|---|
| `year`| Calendar year of the transaction. |
| `month` | Calendar month of the transaction. |
| `date` | Calendar date of the transaction (daily grain). |
| `warehouse` | Warehouse that dispatched the order. |
| `route`| Route that made the sale. |
| `product_code` | Numeric SKU identifier. |
| `product_name` | Commercial description of the SKU. |
| `client_code` | Client identifier. |
| `client_name` | Client name (anonymized). |
| `category` | Product category. |
| `subcategory` | Product subcategory. |
| `brand` | SKU brand (anonymized). |
| `basket`| Commercial basket. |
| `ticket_code` | Unique transaction identifier. |
| `sell_in_quantity` | Units sold. |
| `sell_in_amount` | Net amount charged for the units sold (effective price × quantity). |
| `id_combo` | Combo/promotion identifier, empty if the sale was organic (no promotion). |
| `combo` | Applied combo name, empty if the sale was organic. |
| `bruto` | Amount that would have been charged at list price, no discount (list price × quantity). |
| `discount` | Discount depth applied over list price, as a fraction (0 if organic sale). |
| `product_cost` | Total acquisition cost of the units sold in the transaction (unit cost × quantity). |
| `product_margin` | Fixed profit margin per SKU (markup over cost). Constant for each SKU over the whole period. |

### Data quality notes (intentional)

- `discount`, `bruto`, and `product_cost` have nulls in a fraction of the rows — handled as they would be in a real extract.
- There are transactions with `sell_in_quantity = 0` (cancelled tickets) and transactions with `sell_in_amount = 0` but positive quantity (gift/sample product).
- One row has incomplete product metadata (category/subcategory/brand/basket empty).
